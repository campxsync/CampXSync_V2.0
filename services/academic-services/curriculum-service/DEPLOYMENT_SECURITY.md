## 1. Overview & Security Objectives

This document establishes the security, encryption, and data governance controls for the ACD-02 Curriculum Management Service in compliance with user stories ACD2-63, ACD2-65, and ACD2-66.

---

## 2. Transport Layer Security (TLS 1.2 / TLS 1.3)

### 2.1 HTTPS Server Configuration
The service supports in-transit TLS encryption using Java's embedded `HttpsServer`. When keystore environment variables are supplied, the service boots with an `SSLContext` configured for TLS:

```bash
# Environment variables for production TLS:
export HTTPS_KEYSTORE_PATH="/etc/campx/certs/keystore.jks"
export HTTPS_KEYSTORE_PASSWORD="vault-injected-password"
```

### 2.2 Cipher Suites & Protocol Hardening
- **Protocols Supported:** `TLSv1.2`, `TLSv1.3` (SSLv3, TLSv1.0, TLSv1.1 disabled).
- **Recommended Ciphers:**
  - `TLS_ECDHE_ECDSA_WITH_AES_256_GCM_SHA384`
  - `TLS_ECDHE_RSA_WITH_AES_256_GCM_SHA384`
  - `TLS_ECDHE_ECDSA_WITH_AES_128_GCM_SHA256`
  - `TLS_ECDHE_RSA_WITH_AES_128_GCM_SHA256`

## 3. External API Consumer Authentication (Story 63)

### 3.1 Authentication Mechanism
- External consumers authenticate via the `X-API-Key` HTTP request header.
- API keys are scoped to specific tenants and capabilities (`READ`).
- Unauthenticated or expired keys receive `401 Unauthorized` (`ACD2_UNAUTHORIZED`).

### 3.2 Key Storage & Hashing
- Raw API keys are never stored directly in MongoDB.
- All stored keys are hashed using SHA-256 with tenant salt before persistence.
- Key format: `ak_live_<tenantCode>_<randomEntropy>`.

### 3.3 Authorization Enforcement
- Callers authenticated via `X-API-Key` receive the dedicated `EXTERNAL_API` role.
- `EXTERNAL_API` is strictly granted `CURRICULUM_VIEW` permissions.
- Any attempt to invoke state-modifying operations (`POST`, `PUT`, `DELETE`) is immediately rejected with HTTP 403 `ACD2_FORBIDDEN`.

## 4. Data Classification & Field Filtering (Story 65)

All curriculum data fields are assigned sensitivity classification tiers:

| Tier | Level | Classification | Fields | Permitted Roles |
|---|---|---|---|---|
| **L1** | Public | Publicly accessible metadata | `id`, `name`, `courseId`, `status`, `academicPattern`, `departmentId`, `currentVersion` | All roles including `STUDENT` and `EXTERNAL_API` |
| **L2** | Internal | Academic structure & syllabus | L1 + `totalCredits`, `semesterCount`, `effectiveFrom`, `effectiveTo`, `semesters`, `syllabus` | `FACULTY`, `DEPARTMENT_HEAD`, and above |
| **L3** | Confidential | Audit records & actor attribution | L1 + L2 + `createdBy`, `updatedBy`, `approvedBy`, `publishedBy`, `auditHistory` | `ACADEMIC_ADMIN`, `REGISTRAR`, `ACCREDITATION_TEAM`, `CURRICULUM_COMMITTEE` |
| **L4** | Restricted | Multi-tenant isolation & system keys | L1 + L2 + L3 + `tenantId`, `institutionId`, API keys, encryption keys | `SUPER_ADMIN`, `ADMIN`, `SYSTEM` |

### 4.1 Response Sanitization
The controller dynamically filters JSON fields based on the caller's clearance level before serializing the payload to the wire.

## 5. MongoDB Encryption-at-Rest (Story 66)

### 5.1 WiredTiger Storage Engine Encryption
Production MongoDB clusters must enable WiredTiger native encryption with AES-256-CBC:

```yaml
# /etc/mongod.conf
security:
  enableEncryption: true
  encryptionCipherMode: AES256-CBC
  kmip:
    serverName: kms.campx.internal
    port: 5696
    clientCertificateFile: /etc/ssl/kms-client.pem
```

### 5.2 Backup Encryption
All database backup snapshots generated by `mongodump` must be encrypted using OpenSSL AES-256 before upload to S3/GCS:
```bash
mongodump --archive | openssl enc -aes-256-cbc -salt -out backup_acd02_$(date +%F).enc -pass file:/etc/campx/backup.key
```

## 6. Audit Log Redaction & Masking

1. `X-API-Key` headers are never emitted in plain text to log files; they are masked as `ak_liv...`.
2. Sensitive actor identifiers are preserved only within secured audit collections and redacted from general HTTP ingress logs.
3. Structured logs include correlation and trace identifiers (`X-Trace-Id`) without leaking payload PII.
