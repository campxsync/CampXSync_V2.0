- **Security bugs found in code:**
  1. **Cross-institute write bypass:** `SecurityDomainService.createFinding`, `createRisk`, and `createAlert` read `instituteId` from the client request body *before* falling back to the trusted token (`ctx.getTenantId()`), and PostgreSQL Row-Level Security (RLS) `WITH CHECK` policies on `sec.findings`, `sec.risks`, `sec.alerts`, `sec.control_assessments`, `sec.evidence_refs`, `sec.exceptions`, and `sec.signals` do not enforce `institute_id = core.current_tenant_id()`.
  2. **Missing Separation of Duties (SoD) on exceptions:** `SecurityDomainService.decideException` never checks that the decider (`ctx.getUserId()`) differs from the requester (`requester_user_id`), so Super Admin (R01) can approve their own exception request.
  3. **Service-only signal intake bypass:** `SecurityDomainService.requireAny` automatically passes for Super Admin (R01) and System Admin (R02), allowing human operators to call `/intake/signals` even though `iadm07.signal.intake` is restricted to the `SERVICE` caller.
