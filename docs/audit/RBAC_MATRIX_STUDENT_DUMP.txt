1. Purpose and Scope
This document defines the enterprise-wide role and permission model for CampXSync. It maps organizational roles to microservices and operational permissions while preserving tenant, institution, campus, department, course, section, resource-ownership and workflow boundaries.
The recommended model is hybrid RBAC + ABAC: RBAC establishes what a role may do, while attribute- and policy-based controls determine the data scope in which that action is valid.

16. Effective Permission Model
A user's final permission should be evaluated as:
Effective Access = Role Permission + Role Hierarchy + Tenant Scope + Institution Scope + Campus Scope + Department Scope + Course Scope + Section Scope + Resource Ownership + ABAC Policy + Time/Validity Constraints + Delegation
Example — Faculty:
Faculty → LMS-05 Assignments → Create/Update → Assigned Subject → Assigned Section.
The same faculty member should not automatically receive institution-wide assignment administration.

21. Architectural Principles to Lock
Roles do not directly grant unrestricted access to microservices.
Roles grant permissions to perform specific actions on resources.
ABAC determines the data scope within which those actions are valid.
High-risk workflows must enforce Segregation of Duties.
Valuator, Marks Approver and Result Publisher must be independently controlled.
Financial creation, approval and payment execution must be separated where applicable.
API clients are machine identities and must receive explicit scopes.
Sensitive data should additionally use field-level authorization where required.
Authorization decisions and high-risk administrative actions should be auditable.
Tenant and institution boundaries must be enforced at the authorization and data-access layers, not only in the UI.
22. Summary
The CampXSync authorization architecture should therefore operate as a centralized policy-driven authorization layer spanning all business microservices. The model combines RBAC for role semantics with ABAC/data scopes for contextual access, while workflow permissions such as Review, Approve and Publish provide the separation needed for academic, examination, financial and administrative integrity.
